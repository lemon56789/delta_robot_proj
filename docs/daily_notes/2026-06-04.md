- 왜: `84/86/88 deg`는 SoT 기준 0도와 servo command 기준 0점 사이의 기준 command 값이며, `theta*_meas` offset이나 fine calibration offset으로 부르면 이후 데이터 필드 의미와 혼동될 수 있기 때문이다.
- 어떻게: Arduino 변환식을 `servo_angle_i = center_cmd_i + sign_i * theta_cmd_i + fine_offset_i`로 정리하고, `center_cmd_1=84 deg`, `center_cmd_2=86 deg`, `center_cmd_3=88 deg`, `sign_i=+1`, `fine_offset_i=0 deg`를 measurement calibration table에 기록했다.
- 결과: 현재 하드웨어 기준에서는 `+90 deg` command가 실제 `+90 deg` 이동으로 해석되며, Run 00에서는 arm별 저속 확인으로 `sign_i=+1`과 추가 fine offset 없음이 유지되는지만 검증하면 된다.
- 변경 파일: `docs/hardware_experiment_base_config.md`, `docs/daily_notes/2026-06-04.md`
