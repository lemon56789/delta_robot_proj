## Entry 002
- 무엇을:
  - `docs/plans/2026-05-08_002_update_sot_angle_range_to_minus45.md` 계획서를 작성했다.
  - `docs/system_data_flow.md`, `docs/ik_structure_note.md`, `docs/roadmap.md`, `docs/workspace_envelope.md`, `fulltext.md`의 angle range 기준을 갱신했다.
- 왜:
  - 기존 `0..90 deg` provisional range는 정확한 하드웨어 범위를 몰라 보수적으로 둔 값이었고, 현재 팀 판단 기준에서는 `-45..90 deg`를 임시 운용 범위로 쓰는 편이 더 일관되기 때문이다.
  - 설치 높이와 workspace envelope 문서가 현재 SoT와 서로 다른 angle range를 쓰면 이후 해석과 설계 판단에 혼선이 생기기 때문이다.
- 어떻게:
  - `hardware-confirmed`는 여전히 미확정으로 두고, `hardware-safe provisional`과 `nominal-analysis`를 모두 `-45 deg <= theta_i <= 90 deg`로 맞췄다.
  - workspace envelope 문서의 주의 문구도 현재 SoT 기준에 맞게 갱신했다.
- 결과:
  - 현재 기준 문서들에서 angle range 표현이 `-45..90 deg`로 정렬되었다.
  - 이후 설치 높이, workspace, trajectory safe zone 검토가 같은 범위를 기준으로 이뤄질 수 있게 되었다.

  - 필요하면 코드 기본값과 실험 스크립트 default도 현재 SoT 기준과 완전히 맞춘다.
